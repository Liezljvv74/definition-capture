# Grammar Tutor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A paid grammar tutor at `/tutor` that answers grammar questions through OpenRouter, grounded in reference sites for the studied language, in the app's own rule format, with a one-conversation free trial.

**Architecture:** A Node route handler `POST /api/tutor` verifies the session, reads the plan, usage and settings under RLS, calls OpenRouter's chat completions with built-in `fetch` (JSON-schema reply, Exa web search restricted to per-language domains), validates the reply with the app's block reader, records the question, and returns blocks plus sources. A server page renders the allowance and settings; a client component holds the conversation in memory and saves answers as rules through the existing rule store.

**Tech Stack:** Next.js 16 App Router (route handlers, `proxy.ts`), React 19, Tailwind 4, Supabase (Postgres, RLS, `@supabase/ssr`), OpenRouter REST API, Vitest 3, Playwright 1.63.

**Spec:** `Docs/tutor.md`. Read it before every task.

## Global Constraints

- Next 16 differs from training data: read `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md` before writing the route handler.
- `OPENROUTER_API_KEY` is read only in server modules (`src/lib/tutorServer.ts`, `src/app/api/tutor/route.ts`); never a `NEXT_PUBLIC_` name; never imported by a client component. `OPENROUTER_MODEL` overrides the default model `openai/gpt-5-mini`.
- No new npm dependency.
- Server code uses `getClaims()` (via `serverUserId()`), never `getSession()`. No service-role key anywhere.
- Every new table has RLS in the migration that creates it, policies on `(select auth.uid()) = user_id`; `account_plans` gets select only; `tutor_usage` gets select and insert only. All functions stay `security invoker`; this plan adds no function.
- Limits: free 5 messages in total; paid 30 per UTC day; history cap 10 messages; question max 1,000 characters.
- Copy: exactly the strings in the spec's tables; no price, no "free" on screen, no em dashes, no explanatory "demo speak"; red only for errors.
- Migrations: `npx supabase migration new <name>`, rehearse locally, live `db push` only with the owner's yes, before the code merges.
- Signed-in e2e tests run on localhost only, against the local Supabase copy (CLAUDE.md procedure).
- README, `CLAUDE.md`, `Docs/schema.md`, `.env.example` updated in this branch.
- Comments explain why, in full sentences, at the surrounding density.
- Checks: `npx tsc --noEmit`, `npx eslint src/ e2e/`, `npx vitest run`; `npm run build` in the final task.

## Review Focus

1. **A model reply that is not what the schema promised** (prose, truncated JSON, a table with ragged rows, an unknown block kind, a 50 KB string). The server must return the error state and record nothing. Pinned in Task 3's `readReply` tests.
2. **Someone calling the route directly** with a forged history (system-role messages, 200 messages, a 1 MB question, `plan: "paid"` in the body). The server ignores client-supplied roles other than user/assistant, caps everything, and reads the plan only from the database. Pinned in Task 4's route tests.
3. **An account trying to give itself a paid plan or erase its usage** through the Supabase API. RLS and grants must refuse insert/update/delete on `account_plans` and update/delete on `tutor_usage`. Pinned in Task 1's rehearsal.
4. **A language typed in as "Other", or no native language set.** No web search, the "Not checked against a reference" note, and only the studied language offered as answer language. Pinned in Tasks 3 and 5.
5. **OpenRouter down, out of credit, or slow.** A 4xx/5xx/timeout shows "The tutor could not answer. Try again.", records nothing, and the question box stays usable. Pinned in Task 4.

```sql
-- The grammar tutor (Docs/tutor.md): who may use it, how much, and the two
-- settings it reads. The plan is readable by its account and writable by no
-- one but an administrator, so nobody can upgrade themselves; usage can only
-- grow, so nobody can wind back their count.

create table public.account_plans (
  user_id uuid primary key references auth.users (id) on delete cascade,
  plan text not null default 'free' check (plan in ('free', 'paid')),
  updated_at timestamptz not null default now()
);
alter table public.account_plans enable row level security;
create policy account_plans_select on public.account_plans
  for select to authenticated using ((select auth.uid()) = user_id);
revoke all on public.account_plans from public, anon, authenticated;
grant select on public.account_plans to authenticated;

create table public.tutor_usage (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users (id) on delete cascade,
  created_at timestamptz not null default now()
);
-- Serves the two counts the route makes on every question: all of an
-- account's rows, and its rows since midnight UTC.
create index tutor_usage_user_created_idx on public.tutor_usage (user_id, created_at);
alter table public.tutor_usage enable row level security;
create policy tutor_usage_select on public.tutor_usage
  for select to authenticated using ((select auth.uid()) = user_id);
create policy tutor_usage_insert on public.tutor_usage
  for insert to authenticated with check ((select auth.uid()) = user_id);
revoke all on public.tutor_usage from public, anon, authenticated;
grant select, insert on public.tutor_usage to authenticated;

alter table public.user_settings
  add column native_language text not null default '',
  add column native_language_other text not null default '',
  add column level text not null default '';
-- Same shape as the studied language (copy the exact constraint expressions
-- from 20260924101234_language_and_sort_skip_words.sql):
alter table public.user_settings
  add constraint user_settings_native_language_code check (native_language ~ '^([a-z]{2,3})?$'),
  add constraint user_settings_native_language_one check (native_language = '' or native_language_other = ''),
  add constraint user_settings_native_language_other_length check (char_length(native_language_other) <= 60),
  add constraint user_settings_level check (level in ('', 'A1', 'A2', 'B1', 'B2', 'C1', 'C2'));

-- Checked rather than assumed: the policies and grants are exactly these.
do $$
begin
  if exists (select 1 from pg_policies where schemaname = 'public' and tablename = 'account_plans'
             and cmd <> 'SELECT') then
    raise exception 'account_plans has a write policy';
  end if;
  if has_table_privilege('authenticated', 'public.account_plans', 'insert')
     or has_table_privilege('authenticated', 'public.account_plans', 'update')
     or has_table_privilege('authenticated', 'public.account_plans', 'delete')
     or has_table_privilege('authenticated', 'public.tutor_usage', 'update')
     or has_table_privilege('authenticated', 'public.tutor_usage', 'delete')
     or has_table_privilege('anon', 'public.account_plans', 'select')
     or has_table_privilege('anon', 'public.tutor_usage', 'select') then
    raise exception 'a tutor table has a grant it must not have';
  end if;
end;
$$;
```

If the existing `language_other` length limit differs from 60, use the same number. If the earlier migrations' table-count self-check blocks would now fail (they run only when applied, so they will not), do nothing; they are history.
